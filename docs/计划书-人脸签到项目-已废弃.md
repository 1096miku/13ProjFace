> 注：本文档为历史存档。为满足"项目中不出现厂商标识"的要求，文中的开发板名称与板型标识均已中性化改写，技术内容与决策记录未变。

- 硬件基线：自定义 ESP32-S3 开发板（ESP32-S3-WROOM-1-N16R8 / 16MB Flash / 8MB Octal PSRAM）
- 软件基线：ESP-IDF v5.5.3 + xiaozhi-esp32 v2.2.4（板型 `CUSTOM-ESP32S3-ATTEND`）
- 术语约定见 [`CONTEXT.md`](../CONTEXT.md)；人脸可行性的一手证据见 [`esp32s3-face-recognition-feasibility-research.md`](../esp32s3-face-recognition-feasibility-research.md)

## 0. 摘要

一台教室内的 ESP32-S3 设备，**离线**完成人脸注册、1:N 人脸签到、迟到／缺勤判定与语音播报；联网后把签到事件汇到 PC 后端的数据库，供教师端查询与二次判定。设备同时是小智AI 语音助手：可自由对话，也可用语音查询考勤。

三条决定整个方案的边界：

1. **判定在设备端，事件与结论分离**。断网照常判定；规则与课表由云端下发并缓存到设备；后端拿到原始事件后可重算结论。
2. **人脸比对在设备本地完成**，照片不出设备。这是产品选择（隐私 + 断网可用），不是技术必需。
3. **摄像头与人脸识别分时复用**：待机时摄像头关闭、识别任务挂起，只留唤醒词；进入考勤模式才启动人脸链路。这既是为了给语音对话让出 PSRAM/CPU，也是为了绕开 esp-sr 与 esp-dl 共存时的已知缺陷。

## 1. 目标与验收标准

**目标**：完成一个"单台设备、单班 ≤50 人"的完整演示闭环——注册 → 签到 → 判定 → 播报 → 断网补传 → 后端可查 —— 且每项都有可复现的量化数据。

### 1.1 量化指标（验收用）

| 指标 | 目标值 | 测量条件 |
|---|---|---|
| 人脸注册成功率 | ≥ 95% | 正脸、30–60 cm、室内常规照明，3 次尝试内完成 |
| 1:N 识别 TOP-1 准确率 | ≥ 90% | 50 人库、每人不小于 5 次抽样 |
| 误识别率（他人被认成已注册者） | ≤ 2% | 同上抽样集 |
| 单次识别端到端耗时 | ≤ 0.6 s | 含抓帧；官方基准为检测 37–40 ms + 识别 ~255 ms |
| 考勤判定与规则一致率 | 100% | 规则引擎单测覆盖：正常／迟到／缺勤／重复签到／请假覆盖 |
| 断网 4 h 内签到记录丢失数 | 0 | 拔网线连续签到 |
| 联网后补传完成时间 | ≤ 30 s | 积压 ≤ 1000 条 |
| 运行人脸时的内存余量 | Free PSRAM ≥ 1 MB、Free 内部 RAM ≥ 50 KB | 串口周期打印 |
| 唤醒→对话首次响应 | ≤ 2 s | 依赖官方云，属外部指标，仅记录不承诺 |

### 1.2 不做的（本项目明确排除）

- 活体检测／防照片代签（列为后续研究；设备端不设权限体系）
- 教室环境数据采集（板上无温湿度／光照传感器，需外接模块）
- 微信小程序（列为后续扩展；本周期后端只提供 REST/JSON 与落库）
- 云端 LLM 自动生成报表（后续扩展）
- 巴法云作为主数据通路（仅保留"云端可见"演示链路）
- 多设备共用花名册（人脸库单设备独立）

## 2. 硬件事实与约束

### 2.1 板上已确认可用

| 子系统 | 事实 |
|---|---|
| 主控 | ESP32-S3-WROOM-1-N16R8，16 MB Flash + 8 MB Octal PSRAM（IO35/36/37 专用，不可复用） |
| 摄像头 | DVP 座 J6，实装 GC0308（VGA）。XCLK=IO5、PCLK=IO7、VSYNC=IO3、HREF=IO46、D0–D7=IO16/18/8/17/15/6/4/9；PWDN 走 PCA9557 P2；SCCB 复用 I2C0(IO1/IO2)、地址 0x21 |
| 屏幕 | ST7789 4 线 SPI2，480×320 横屏；SCK=IO41、MOSI=IO40、DC=IO39、BL=IO42；CS 走 PCA9557 P0；**MISO 未接回 MCU（只写不可读）** |
| 触摸 | FT6336 @0x38（屏模组内），INT=IO10 |
| 音频 | ES8311(0x18) 播放 + ES7210(0x41) 录音 + NS4150B 功放；I2S：MCLK=38、BCLK=14、WS=13、DOUT=45、DIN=12；PA_EN 走 PCA9557 P1（高有效） |
| IO 扩展 | PCA9557 @0x19：P0=LCD_CS、P1=PA_EN、P2=CAM_PWDN、P3–P7=EXT-IO1~5（H1 排针） |
| 其他 | 用户按键 SW3=IO11；LED6=IO10（与 CTP_INT、CN2 共用，需仲裁）；TF 卡槽（本方案不使用） |

### 2.2 板上的缺口（设计必须绕开）

- **无 RTC 芯片**：断电即失时，只能靠联网校时 + 内部 RTC 漂移（见 §5.4）。
- **无环境传感器、无蜂鸣器、无电池／充电电路**。
- **GC0308 驱动能力受限**：`brightness / quality / aec2 / awb_gain` 等控制项均为空实现（返回 -1），无自动对焦 → 光照变化下识别率下降无法自适应。
- **IO10 三占**（触摸 INT + LED6 + CN2）：本方案用 LED6 表示考勤模式状态时须确认与触摸中断不冲突，冲突则放弃 LED 指示。

### 2.3 动手前必修项

| 项 | 现状 | 处理 |
|---|---|---|
| Flash 大小配置 | `11_PCA9577/sdkconfig` 为 2 MB，与 16 MB 硬件不符 | 基线工程按 16 MB + Octal PSRAM 重建配置 |
| PSRAM | 当前未开启 | 开启 `SPIRAM_MODE_OCT` + `SPIRAM_SPEED_80M` |
| DVP 数据脚位 | 原理图只给出脚位集合，未逐脚核对 | D1 用实际出图与 `esp32-camera` 驱动日志核对 |
| 摄像头 SCCB 端口 | `sdkconfig` 曾为 PORT1 | 统一到 `I2C_NUM_0` |

## 4. 系统架构

### 4.1 设备端

```
                    ┌──────────────── 考勤模式（叠加层，独立于对话状态）────────────────┐
                    │  摄像头→人脸检测→1:N 识别→签到事件→规则判定→结论→播报/上屏/入库  │
                    └───────────────┬──────────────────────────────┬───────────────────┘
  LVGL 9.4 UI ── 常亮课次页 / 注册页 / 记录页 / 考勤统计页 / 考勤按钮           │                   │
  小智AI ── 唤醒词(WN9) → 对话(服务端 ASR/LLM/TTS) → MCP 工具(考勤查询)              │
  PCA9557 ── LCD_CS / PA_EN / CAM_PWDN                                            │
  存储 ── NVS(配置/课表/时间基准) + Flash 文件(人脸库/事件队列)                      │
  通道 ── 巴法云 MQTT(实时事件·演示可见)      局域网 HTTP(补传·可重试幂等) ◄─────────┘
```

**分时复用（硬约束）**：

| 状态 | 摄像头 | 人脸识别任务 | 唤醒词/对话 |
|---|---|---|---|
| 待机 | 关闭（`self.camera.set_enabled(false)`） | 挂起 | 常驻 |
| 考勤模式 | 开启（QVGA RGB565） | 运行 | 可暂停（进入考勤时挂起唤醒，退出后恢复） |
| 补传 | 关闭 | 挂起 | 允许 |

**考勤模式状态机**：由课次开始时间自动进入、课次结束自动退出；手动入口为屏幕按钮、SW3(IO11) 长按、联网时语音指令；三者共用同一切换语义（开始／提前结束）。它与小智的 `device_state` 正交：可以一边对话一边处于考勤模式。

### 4.2 PC 后端

- 技术栈：Windows 本机 + Python（FastAPI）+ SQLite。
- 职责：① 订阅巴法云 MQTT 落库；② 接收设备经局域网 HTTP 的批量补传（幂等键去重）；③ 下发课表 JSON；④ 提供 REST/JSON 查询接口（小程序阶段直接复用）。
- 部署：演示时本机运行；不依赖公网可达（小程序阶段再考虑内网穿透或云主机）。

### 4.3 存储与分区

**问题**：`xiaozhi.bin` 已占 2.86 MB，`ota_0` 只有 4.13 MB，**app 分区只剩约 1.08 MB**，人脸模型（1.42 MiB）编进 app 不可行。

**方案**：模型走官方支持的"独立 flash 分区"加载方式，把 `assets` 分区（8 MB，实际只用了 2.72 MB）切出一部分：

| 分区 | 大小 | 用途 | 依据 |
|---|---|---|---|
| `human_face_det` | 0x40000（256 KB） | 检测模型（MSR 61,168 B + MNP 129,968 B） | 官方要求子类型 spiffs、尺寸大于模型 |
| `human_face_feat` | 0x200000（2 MB） | 识别模型（MFN 1,295,168 B） | 同上 |
| `assets` | 余量约 5.75 MB | 唤醒词模型/字体/音效/表情 | 现用 2.72 MB，切分后仍充裕 |

附带收益：`assets` 尺寸变小，缓解"SPI flash mmap 空闲页需 ≥ 分区大小"的约束。

**实施中的修正（实测驱动）**：链接 esp-dl 检测链路后，`xiaozhi.bin` 从 2.86 MB 涨到 **4.43 MB（+1.58 MB）**，4.13 MB 的 `ota_0` 直接溢出 511 KB。因此改用 `partitions/v2/16m-attend.csv`：**去掉 `ota_1`，`ota_0` 扩到 7.875 MB**，`assets` 与两个模型分区偏移不变。

| 分区 | 偏移 | 大小 | 说明 |
|---|---|---|---|
| `ota_0` | 0x20000 | 0x7E0000（7.875 MB） | 单 app 槽；实测占用 4.43 MB，余 44% |
| `assets` | 0x800000 | 0x5C0000（5.75 MB） | 现用 2.72 MB |
| `human_face_det` | 0xDC0000 | 0x40000（256 KB） | 检测模型打包后 191,248 B |
| `human_face_feat` | 0xE00000 | 0x200000（2 MB） | 识别模型 1,295,168 B |

**代价：失去 A/B OTA 升级能力。** 本板已禁用自动升级、固件经 USB 烧录，且无备用槽时 `self.upgrade_firmware` 工具会失败。保留双槽的方案是"两槽各 5.25 MB + `assets` 压到 3.125 MB"，但 app 余量仅约 0.8 MB 且识别代码尚未链接，风险更高，故未采用。

**数据存放**：

| 数据 | 位置 |
|---|---|
| 课表、考勤规则、时间基准、设备配置 | NVS |
| 人脸库（一人 2050 B：2 B 编号 + 512 维 float32） | Flash 文件，≤50 人约 100 KB |
| 签到事件队列（断网积压，目标 ≥1 万条） | Flash 文件，环形/追加写 + 待传标记 |
| 人脸照片 | **不存**（演示版决定） |

## 5. 关键设计

### 5.1 人脸链路（含退路）

- 检测：`MSRMNP_S8_V1`（两级：MSR 粗检 + MNP 精修），输入由摄像头 QVGA RGB565 缩放而来。
- 识别：`human_face_feat_mfn_s8_v1`（MFN，1.2 M 参数，248.8 ms/帧）；**不用 MBF**（3.4 M 参数、1072 ms，太慢且模型 3.5 MB）。
- 已知必踩的坑：**RGB565 端序**。ESP32-S3 是小端 RGB565，与 P4 相反；IDF 5.5.x 上存在 `DL_IMAGE_CAP_RGB565_BIG_ENDIAN` 相关的公开 issue。D2 的首要任务就是把它调通（备选：改 YUV422 或手工转换）。
- **退路（触发条件：D3 结束仍无法稳定识别）**：保留人脸检测 + 屏幕数字键盘输入学号，签到身份由学号确认。界面与流程不变，只是身份来源从"人脸比对"降为"人脸在场 + 学号"，计划书与演示口径同步改写。

### 5.2 考勤规则（可直接实现的口径）

| 规则 | 取值 |
|---|---|
| 迟到阈值 | 云端下发，默认 5 分钟，**下限 5 分钟**（吸收时钟误差） |
| 结论取值 | 正常／迟到／缺勤 |
| 结论生成 | 课次内**首次**成功识别即定结论；后续识别只累计"重复签到"次数 |
| 缺勤结算 | 课次结束时间到点，由设备端定时器结算未到者 |
| 请假 | 设备端不处理；教师在后端把"缺勤"覆盖为"请假"，只重算结论，签到事件不变 |

**判定优先级（必须单测覆盖）**：先判定"该人脸是否属于本课次应到名单" → 再按首次识别时间与阈值定 正常／迟到 → 课次结束统一结算 缺勤 → 重复识别只计数。

### 5.3 时间与"时间不可信"处理

- 联网时：由 xiaozhi 的 OTA 响应下发服务器时间（`main/ota.cc` 的 `server_time.timestamp/timezone_offset` → `settimeofday`），设备据此校准。
- 断网且断电重启：内部 RTC 失时。此时**允许签到**，但记录带 `time_trusted=false` 与相对标识（课次编号 + 设备运行毫秒数），屏幕明确显示"离线时间"。
- 恢复联网：设备补发一条**时间校准事件**；后端据此把不可信记录映射到绝对时间并重算结论（这正是"事件与结论分离"的用武之地）。
- 迟到阈值的 5 分钟下限，用来吸收内部 RTC 数小时内的漂移。

### 5.4 语音与播报

- **播报只播通用整句，姓名只上屏**。固件没有"运行时播放任意音频"的接口，只有编译期内嵌 OGG（`AudioService::PlaySound`），因此提示音必须作为资源编入 `main/assets/common/`。提示音清单控制在 8–10 条（签到成功／迟到／缺勤／未注册／请重试／查询结果等），避免挤占 app 分区。
- 手动/联网语音播报（"张三，签到成功"这类含姓名的句子）**不做**；如后续要做，走服务端 TTS 生成音频缓存方案。
- **语音查询考勤**走 xiaozhi 的 MCP 扩展点：在板级 `InitializeTools` 注册 `self.attendance.query`（参数：学号或"我"），由 LLM 调用后播报结果。仅联网可用。
- 断网时：对话不可用（ASR/LLM/TTS 都在服务端），考勤判定、屏幕、内置提示音全部照常。

### 5.5 上报与补传

| 通道 | 内容 | 触发 |
|---|---|---|
| 巴法云 MQTT | 实时签到事件（演示"云端可见"） | 在线时即时 |
| 局域网 HTTP | 断网积压记录批量补传 | **待机或课次结束后**触发，对话期间不补传 |

补传要求：带幂等键（设备 ID + 事件序号 + 时间戳）、支持断点续传与确认应答，后端按幂等键去重。

### 5.6 人脸注册流程

屏幕引导 → 摄像头抓 3–5 帧 → 取质量最优一帧提特征 → 屏幕数字键盘输入学号 → 存入人脸库 → 提示音"注册成功"。全程离线，不做云端唯一性校验（重复／重名由后端人工清理）。不保存照片。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 唤醒词与人脸共存缺陷（esp-dl / esp-sr 已公开 issue：命令词初始化后人脸框异常、MultiNet 占用约 3 MB PSRAM、WN10 加载失败） | 识别结果错乱或模型加载失败 | 分时复用（待机不跑人脸）；D1 实测选 esp-sr 版本；内存余量指标纳入每日验收 |
| RGB565 端序 / IDF 5.5.x 兼容坑 | D2 卡住 0.5–1 天 | 优先调通单帧检测；备选 YUV422 或手工转格式 |
| 官方 xiaozhi.me 对本地新增板型无书面保证，且 OTA 会用标准固件**静默覆盖**自定义固件（`CheckNewVersion()` 检测到新版本即刷机重启，无需确认） | 整周成果被覆盖 / 设备无法激活 | 已改代码：唯一板型标识 `CUSTOM-ESP32S3-ATTEND` + 本板跳过自动升级分支；**D1 预留半天做自建服务端兜底验证**；兜底栈已明确：DeepSeek API（已有）+ 本地 FunASR + EdgeTTS，无需额外付费 key |
| app 分区装不下人脸链路 | 链接 esp-dl 后 app 从 2.86 MB 涨到 4.43 MB，原 4.13 MB 槽溢出 511 KB | **已解决**：改用单槽 7.875 MB 分区表（`16m-attend.csv`），实测余 44%；提示音仍控制在 10 条内，每日记录 app 体积 |
| GC0308 无 AEC/AWB、无自动对焦 | 光照变化下识别率下降 | 演示环境固定照明；如实写入限制章节；必要时固定曝光参数 |
| 无活体检测 | 照片可代签 | 明确列为已知限制，不作为身份认证；写进限制与后续研究项 |

## 8. 测试与指标测量方法

- **规则引擎单测**：正常／迟到（阈值边界 ±1 分钟）／缺勤／重复签到／请假覆盖，在 PC 侧用同一份规则实现跑用例，再与设备端实测比对。
- **识别指标**：50 人库，每人 5 次不同光照/距离抽样，记录 TOP-1 命中与误识别；用串口日志输出每次耗时。
- **断网与补传**：拔网线连续签到 30 次 → 恢复网络 → 计时补传完成时间 → 数据库核查条数与去重。
- **内存**：周期性打印 Free PSRAM / Free 内部 RAM，取人脸识别运行中的最小值。
- **每天记录 app 与 assets 镜像体积**，防止分区被悄悄撑爆。

## 附录 A：三期设计澄清中被推翻或修正的判断

| 早期设想 | 最终结论 |
|---|---|
| 设备端只做离线命令词，不做自由对话 | **推翻**：设备端保留小智AI 自由对话（项目硬性要求），考勤与对话分时共存 |
| 人脸特征每人 512 字节 | **修正**：每人 2050 字节（2 B 编号 + 512 维 float32） |
| 模型只能编进 app，4 MB 分区可能不够 | **修正**：模型可放独立 spiffs 分区，从 assets 切分即可 |
| 巴法云作为主数据通路 | **修正**：巴法云只做演示可见链路，补传走局域网 HTTP |
| 环境数据采集（I2C/ADC） | **砍掉**：板上无传感器，需外接模块 |
| 断网仅影响上报 | **修正**：断网同时意味着自由对话不可用，仅考勤与播报可用 |
