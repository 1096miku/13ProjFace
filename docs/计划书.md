# 车载AI行车状态监测与语音交互终端 · 计划书

- 版本：v1.0（新项目立项版，承接上一个项目的硬件与环境调研结论）
- 硬件基线：自定义 ESP32-S3 开发板（ESP32-S3-WROOM-1-N16R8 / 16MB Flash / 8MB Octal PSRAM / 480×320 横屏，带触摸与摄像头）
- 软件基线：ESP-IDF v5.5.3 + xiaozhi-esp32 v2.2.4（板型 `VEHICLE-ESP32S3-TERM`）
- 交付周期：**7 天**（每天 8–12 小时），交付物见 §13
- 术语见 [`CONTEXT.md`](../CONTEXT.md)；硬件一手证据见 [`esp32s3-face-recognition-feasibility-research.md`](../esp32s3-face-recognition-feasibility-research.md)（该报告的人脸结论本项目不使用，但其中的**板级硬件事实、内存实测、依赖锁定**全部复用）

## 0. 摘要

一台车内 ESP32-S3 终端：**用板载 IMU 监测行车状态**（急加速/急刹车/急转弯/颠簸/碰撞/停车），**用摄像头 + 环境传感器监测车内环境**，**用屏幕显示状态与实时画面**，**用语音做离线查询与播报**，**联网后把事件上报巴法云供手机远程查看**，并**对接小智AI 做车载问答**。

三条决定方案的边界：

1. **行车状态监测靠板载 QMI8658A IMU**（现成硬件，不需等采购）——这是题目的核心，且**不依赖任何设备端视觉推理**。
2. **"车内人员遗留监测"不靠设备端识别人**：锁车后自动抓拍上传，由手机端人工确认（已确认选择）。
3. **环境传感器（温湿度/光照）预留接口**：软件层抽象为 `EnvironmentSensor`，无硬件时用模拟数据源，界面/上报/语音三条链路照常真实跑通；采购到位后只替换实现。

## 1. 目标与验收指标

**目标**：单人可完成的完整闭环演示——上车通电 → 屏幕显示环境与状态 → 行车中识别四类驾驶事件 → 停车后自动进入锁车监测 → 异常震动触发抓拍与上报 → 手机端看到事件与图片 → 语音查询"车内温度""有没有人" → 小智AI 车载问答。

### 1.1 量化指标

| 指标 | 目标值 | 测量条件 |
|---|---|---|
| 四类驾驶事件识别准确率 | ≥ 90% | 手持板模拟动作各 10 次（急加速/急刹/急转/颠簸） |
| 事件响应延迟 | ≤ 300 ms | 从动作发生到屏幕出现事件提示 |
| 停车判定延迟 | ≤ 30 s（演示值，可配） | 静止持续 `static_hold_ms` 后进入停车态 |
| 温度/湿度/光照刷新率 | ≥ 1 Hz | 有硬件时；无硬件走模拟源同样满足 |
| 摄像头实时预览帧率 | ≥ 10 fps | 320×240 抓帧 → 480×320 屏显 |
| 锁车抓拍上传时延 | ≤ 5 s（局域网） | 触发到 PC/手机端可看到图片 |
| MQTT 上报成功率 | ≥ 99%（联网时） | 事件逐条上报巴法云 |
| 离线语音命令词识别率 | ≥ 90% | 安静车内环境，8 条命令词各 10 次 |
| 运行内存余量 | Free 内部 RAM ≥ 15 KB、Free PSRAM ≥ 5 MB | 全功能并行运行时周期打印 |
| 连续运行稳定性 | ≥ 2 小时无重启无丢数据 | 边预览边监测边上报 |

### 1.2 明确不做的

- 设备端视觉推理（不跑人脸/人体检测模型——上一个项目已证明本板该路径不可用，详见附录 A）
- 车辆 CAN/OBD 数据接入（板上无 CAN 收发器，也不在题目要求内）
- 手机 App/小程序开发（用巴法云自带的小程序/APP 订阅查看）
- 公网查看原图（状态与事件可公网看；原图走局域网，如答辩要求外网再评估内网穿透）

## 2. 硬件事实与约束

### 2.1 板上已有（全部已实测可用）

| 子系统 | 事实 |
|---|---|
| 主控 | ESP32-S3-WROOM-1-N16R8，16MB Flash + 8MB Octal PSRAM（IO35/36/37 专用） |
| IMU | **QMI8658A 六轴 @0x6A**（SDO/SA0 悬空）。**INT1/INT2 未接，只能轮询采样** |
| 摄像头 | DVP 座 J6，实装 GC0308（QVGA RGB565 出图正常）；PWDN 走 PCA9557 P2 |
| 屏幕 | ST7789 4 线 SPI，480×320 横屏；CS 走 PCA9557 P0；MISO 未接（只写） |
| 触摸 | FT6336 @0x38 |
| 音频 | ES8311(0x18) 播放 + ES7210(0x41) 录音 + NS4150B 功放；PA_EN 走 PCA9557 P1；I2S：MCLK=38/BCLK=14/WS=13/DOUT=45/DIN=12 |
| IO 扩展 | PCA9557 @0x19（P0=LCD_CS、P1=PA_EN、P2=CAM_PWDN、P3–P7=EXT-IO1~5） |
| 扩展口 | CN1（SDA/SCL/3V3/GND/VBUS）、H1 八针排针（EXT-IO1~5） |
| 按键/LED | SW3=IO11；LED6=IO10（与 CTP_INT、CN2 共用，本方案不驱动该灯） |

### 2.2 板上没有（设计已绕开）

- **无温湿度传感器、无光照传感器**（I2C 上仅 0x19/0x18/0x41/0x6A/0x38/摄像头 0x21）→ 预留接口
- **无 RTC 芯片**（时间靠联网校时，断网靠内部 RTC 漂移）
- 无电池/充电电路、无蜂鸣器（提示音走喇叭）、无 CAN/OBD

### 2.3 外接硬件（后续接入，软件先留好接口）

| 需求 | 建议器件 | 接口 | 地址/引脚 |
|---|---|---|---|
| 温度+湿度 | SHT30/SHT31 | I2C（CN1） | 0x44/0x45（与现有地址无冲突） |
| 光照 | BH1750 | I2C（CN1） | 0x23（无冲突） |
| 遗留监测辅助（可选） | AM312 红外 | H1 扩展 IO | 任选 EXT-IO1~5 |

> ⚠️ **不要买 AHT20**——地址 0x38 与板上触摸芯片 FT6336 冲突。
> ⚠️ ADC 引脚已几乎占满（ADC1=IO1–10 被 I2C/DVP/触摸占；ADC2=IO11–20 被按键/I2S/USB 占），若必须用 ADC 采集模拟传感器，需提前定脚并自搭分压。

## 3. 系统架构

### 3.1 设备端任务划分（FreeRTOS）

| 任务 | 周期/触发 | 职责 | 备注 |
|---|---|---|---|
| `imu_task` | 20 ms 轮询 | 采样 QMI8658A，喂给状态判定 | IMU 无中断脚，只能轮询 |
| `env_task` | 1 s | 读环境传感器（抽象层；无硬件时读模拟源） | |
| `monitor_task` | 事件驱动 | 状态判定、事件入队、锁车/停车状态机 | 纯逻辑，可主机单测 |
| `camera_task` | 按需 | 抓帧 / 预览 / 锁车抓拍 JPEG | 与预览互斥，避免抢 PSRAM 带宽 |
| `ui_task` | LVGL 内部 | 页面刷新（环境数据、状态、事件、预览） | 复用 xiaozhi 的 LVGL 任务 |
| `net_task` | 事件驱动 | 巴法云 MQTT 上报、局域网 HTTP 上传原图 | |
| 语音链路 | 唤醒词常驻 | 唤醒 + 离线命令词 + 播报 | 复用 xiaozhi 音频栈 |

**资源共存原则**（依据上一个项目的实测内存账）：唤醒词常驻约占 40 KB 内部 RAM，摄像头帧缓冲与预览缓存走 PSRAM。**预览开启时暂停高频抓拍**，避免 SPI 与 PSRAM 带宽争抢。

### 3.2 数据流

```
QMI8658A ─20ms─► monitor_task ─事件─┬─► ui_task（屏幕提示）
                                    ├─► 播报（预录片段）
                                    └─► net_task（巴法云 MQTT / 事件）
环境传感器 ─1s──► env_task ─值─────┼─► ui_task（环境页）
（或模拟源）                        ├─► 语音查询应答（命令词→读值→播报）
                                    └─► net_task（周期上报）
GC0308 ─预览─► ui_task（实时画面）
       └抓拍─► net_task（局域网 HTTP 上传原图 → 手机人工确认）
小智AI ─唤醒/对话─► 官方云（已验证可用）
```

### 3.3 云端与手机端

| 通道 | 内容 | 说明 |
|---|---|---|
| 巴法云 MQTT | 事件（类型/时间/数值）、环境数据周期上报、设备状态 | 手机用巴法云小程序/APP 订阅即可**远程查看（外网可用）** |
| 局域网 HTTP | 抓拍原图（JPEG） | 设备上起一个小 HTTP 服务；手机在同一 Wi-Fi 下打开即看原图 |
| 小智AI 官方云 | 语音对话、车载问答 | 已激活可用 |

## 4. 行车状态判定口径（核心）

以板载 IMU 采样为唯一输入，约定安装方向：**ax 沿车头方向（纵向）、ay 横向、az 垂直（重力方向）**；安装方向偏差通过"静止基线标定"吸收（取静止 1 s 的均值作为零点）。

| 事件 | 判定条件 | 防抖 |
|---|---|---|
| 急加速 | ax − baseline ≥ +0.35 g | 同类型事件冷却 3 s |
| 急刹车 | ax − baseline ≤ −0.35 g | 同上 |
| 急转弯 | \|ay − baseline\| ≥ 0.30 g | 同上 |
| 颠簸 | 合成加速度 \|a\| ≥ 1.6 g 且 < 2.5 g | 同上 |
| 碰撞 | 合成加速度 \|a\| ≥ 2.5 g | 冷却 10 s，并立即抓拍 |
| 停车 | 合成加速度持续在静止带（±0.06 g）内 ≥ `static_hold_ms`（演示 30 s） | — |
| 锁车后异常震动 | 处于锁车监测模式时出现 ≥ 0.25 g 的加速度变化 | 冷却 10 s，并抓拍 |

所有阈值与时长**可配**（`MonitorConfig`），便于现场按实际安装与路况调整。判定逻辑**不依赖 ESP-IDF**，可在 PC 上用 g++ 跑单元测试（见 §12 测试项）。

**锁车监测模式**（已确认 Q2 方案 A+B）：
- 自动：停车态持续 2 分钟后自动进入（阈值可配）
- 手动：屏幕按钮，或语音"锁车"覆盖
- 退出：检测到持续运动，或屏幕/语音解锁

## 5. 环境数据（预留接口）

抽象层设计：

```
EnvironmentSensor（接口）
├── SimulatedSensor   ← 无硬件时使用：温湿度/光照按可配置的基线 + 缓变生成
└── I2cEnvSensor      ← 后续接入：SHT3x(0x44/0x45) + BH1750(0x23) 驱动
```

- 选择方式：Kconfig 开关（`CONFIG_VEHICLE_ENV_SIMULATED`），默认开启模拟源
- **无硬件期间，界面显示、周期上报、语音查询三条链路全部真实跑通**（只有数据来源不同），接上模块只换实现、不改上层
- 数据用途：环境页显示、周期上报巴法云、语音命令词"车内温度/车内湿度/光照多少"的应答

## 6. 遗留监测流程（已确认方案 B）

```
停车 2 分钟 ──► 自动进入锁车监测模式
                     │
        ┌────────────┴────────────┐
        ▼                         ▼
  进入时抓拍 1 张           每次异常震动抓拍 1 张
        │                         │
        └──────────► 事件 + 图片 ◄┘
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
 巴法云 MQTT：事件+时间+加速度值   局域网 HTTP：JPEG 原图
 （手机远程可见）                  （同一 Wi-Fi 打开查看）
                        │
                        ▼
              手机端人工确认"是否有人遗留"
```

**为什么不做设备端自动判断**：上一个项目已用 3 个模型 × 2 个 esp-dl 版本 × 2 条权重加载路径证明——本板 esp-dl 推理输出与输入无关（附录 A），**设备端视觉推理不可用**；改用"抓到就上传、人来看"的方案，既不依赖未验证的推理，又恰好符合车内遗留监测的实际处置流程（安全相关判断由人确认更稳妥）。

## 7. 语音交互

| 能力 | 实现 | 联网要求 |
|---|---|---|
| 唤醒 | ESP-SR WakeNet（`wn9_nihaoxiaozhi_tts`，已跑通） | **离线** |
| 离线命令词 | ESP-SR MultiNet（需在小智固件上补回；原工程为改用云端大模型已移除） | **离线** |
| 播报 | 预录片段 + 数字拼接（ESP-SR 不含 TTS） | **离线** |
| 车载问答 | 小智AI 官方云（已激活可用） | 需联网 |

**离线命令词清单（8 条，已确认）**：`车内温度` / `车内湿度` / `光照多少` / `有没有人` / `设备状态` / `播放提示音` / `重新抓拍` / `锁车`。

> `有没有人` 的口径：**不调用设备端视觉推理**，而是读取"最近一次锁车抓拍是否被手机端标记为有遗留"的本地状态位 + 停车态下是否有异常震动，播报"未检测到异常"或"有遗留提醒待确认"。这条口径会如实写进报告，避免与"视觉自动判断"混淆。

## 9. 联网与上报

- **巴法云 MQTT**：设备端另起一个 `esp-mqtt` 客户端（独立于 xiaozhi 自带的 MQTT+UDP 协议），主题约定：
  - `vehicle/{device_id}/event` —— 事件 JSON（类型、时间戳、加速度值）
  - `vehicle/{device_id}/env` —— 环境数据（周期 30 s）
  - `vehicle/{device_id}/status` —— 在线状态与行车状态
- **局域网 HTTP**：设备起轻量 HTTP 服务，提供 `/latest.jpg`（最近一张抓拍原图）与 `/events`（事件 JSON），供同一 Wi-Fi 的手机浏览器直接查看。
- **断网行为**：事件写入本地队列（目标 ≥ 500 条），恢复联网后按序补传（幂等键 = 设备 ID + 事件序号）；**监测、预览、语音命令词、播报在断网时全部照常工作**。

## 11. 已知限制与风险

| 项 | 说明 | 应对 |
|---|---|---|
| IMU 无中断脚 | 只能轮询（20 ms），高加速度瞬态可能漏采 | 50 Hz 采样足够覆盖驾驶事件；如实写入限制 |
| 安装方向未知 | 阈值判定依赖 ax/ay/az 与车体方向一致 | 静止基线标定 + 阈值可配 + 界面显示三轴实时值便于现场核对 |
| 环境传感器未到位 | 温湿度/光照数据源为模拟 | 抽象层 + Kconfig 开关；文档中明确标注"模拟数据" |
| 摄像头预览与抓拍抢带宽 | 同开可能掉帧 | 预览期间暂停高频抓拍；预览与抓拍互斥调度 |
| 播报无 TTS | 只能预录片段 + 数字拼接 | 片段控制在 10 条内；复杂语句改为屏幕显示 |
| 巴法云免费版限制 | 消息频率/大小有限 | 二进制图片不走 MQTT；事件消息精简并合并上报 |
| 小智AI 依赖官方云 | 断网时车载问答不可用 | 离线命令词覆盖核心查询；文档写明降级行为 |
| 7 天工期 | 功能点较多 | §12 日程带缓冲；每项都有可砍到底线的版本 |
